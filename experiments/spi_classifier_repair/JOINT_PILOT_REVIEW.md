# Joint cached-feature pilot review

Bounded source assessment, 2026-10-28. Inspected `JOINT_BENCHMARK.md` and `head_matrix.py`; no benchmark duplication, worker interruption, model run, or production edit. **Quality-path inspection finds no demonstrated label leakage in this pilot. Current artifacts support a cached-feature, CPU head-only comparison, not whole-pipeline CPU/GPU Pareto conclusions.** Three reporting/failure gaps should be closed before reusing the runner for consequential cross-environment comparisons; existing pilot output can be preserved and qualified without interruption.

## Findings

1. **P2: result identity/provenance is dropped.** `run_family` gets the validated identity from `prepare`, but does not include it in `result.json`. The result also lacks feature/label file hashes, source hash/revision, library versions, host/CPU/thread/backend identity, train/validation IDs and fold membership. Parent directory encoder names cannot establish exact feature or software identity. Persist the verified signature/rubric/source identity, input hashes and host/software/thread metadata, with fold IDs/group/class support where practical. This matters particularly because the earlier local/cloud sklearn comparison already had a version mismatch. Runtime artifacts/logs may independently supply some facts, but the current result object alone does not.

2. **P2: timeout loses captured process output.** In `main`, the family log is written only after `subprocess.run` returns. `TimeoutExpired` bypasses that write, so collected partial stdout/stderr are not persisted; aggregate results only store a short failed reason. Existing `outer_progress.json` survives completed folds, which is useful but incomplete. Write timeout output/stderr to the family log, save terminal failed status and stage/elapsed time, and retain partial folds. Keep failures distinct from unsupported model families, zero performance, and legitimate quality-gate failures. Ordinary nonzero returns already preserve logs. Do not restart the active pilot solely to retrofit this.

3. **P2: convergence warning scope is incomplete.** `warnings.catch_warnings(record=True)` surrounds nested search only. Final full-training fit and inference happen outside it, while result.warnings has no scope label. A final MLP convergence warning can appear only in the subprocess log and is absent from result.warnings, potentially misrepresenting whether the deployed fitted head converged. Capture and tag search/final-fit warnings separately, or explicitly label the existing field CV-only and reference the complete family log. Nonconvergence is a reported optimization limitation, not automatic proof that predictions are invalid.

## Correct mechanisms and interpretation limits

- `prepare` verifies feature/label ID and content-hash joins, grouped roles, consistent rubric/source and four-class training support. Normalization performed before CV is independent per example, not a fitted dataset-level transform. Every inner search sees only its outer training groups. Outer OOF scoring is nested within a fixed head family; final hyperparameters are chosen from training-only grouped CV before fitting all training rows and descriptively evaluating the 96 exposed development rows.
- Fold checks reject training splits missing a class and group overlap. Scoring uses explicit four-class macro-F1 even if a score fold lacks a class. The protocol's requested fold/class-support records are not currently serialized; avoid silently implying every scoring fold has every class.
- No 96-row score enters `choose`. However printing all development scores exposes them to the investigator; do not later choose a winner based on those scores while claiming they were untouched. Ranking encoder/family combinations from their OOF estimates is still selection over these estimates: nested within-family OOF is not an unbiased final estimate for the winning pair selected across encoders/families. No new final-test claim is justified.
- Equal two-configuration grids and common deterministic grouped folds establish a bounded common protocol, not equally exhaustive optimization or a universally fair best-head search. MLP and distance-weighted kNN have different imbalance treatment from explicitly balanced linear/tree families; report that modeling choice. The protocol lists decision tree, ordinal cumulative logit and a strong dummy reference, which this nine-family pilot does not implement. Label coverage as pilot subset and preserve the existing majority reference; do not describe the whole protocol as completed.
- A fresh subprocess isolates each family from other families. RSS fields still include imports, all data, CV allocator retention and model state; the source explicitly says so. Inference RSS after CV is not deployed-model RAM, and it cannot define a deployment-memory Pareto front. RSS polling every 2ms is a sampled peak that can miss short spikes. Do not add independently sampled phase peaks or subtract them to invent model-only memory.
- Final-fit seconds exclude CV; full_search_seconds includes preparation and training-only nested search but excludes final fit/serialization/timing. Batch-one prediction latency has 10 warmup and 100 measured calls under one thread; it excludes encoder extraction, per-row normalization, image loading, transfer, deserialization and full-pipeline cold load. Joblib bytes describe the fitted classifier artifact, not runtime RAM or complete image encoder/checkpoint dependencies. Cached SigLIP/CLIP head timing cannot supply encoder CPU/GPU latency.
- Training FLOPs are null with a reason; linear/MLP dense inference proxies correctly omit bias/activation/control and do not claim exact algorithm FLOPs. Trees/SVM inference remains unsupported rather than zero. No probability metrics are reported for decision-score-only models.
- Local CPU searches use no new GPU by design. The parent applies a 180-second wall timeout per family worker. No measured whole-pipeline CPU/GPU resource comparison or GPU utilization follows from this pilot. Cloud same-host image-in/output profiling, joint memory measurement, transfer costs, pinned image encoders and resource enforcement remain required before the joint benchmark's stronger claims.

## Disposition

Preserve current results, identify failures and warnings, and report them as the bounded cached-feature pilot. No automatic production promotion or release-gate change is warranted; the source marks promotion false. The >=0.70 per-class gate remains an independent quality criterion even for a Pareto-efficient observed pair. No additional model search or tuning was performed by reviewer.
