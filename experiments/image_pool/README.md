# Diverse image pool

Open `Image_Pool_Caching.ipynb`; `PLAN.md` is the canonical specification.
`SOURCES.md` records verified access paths and unavailable inputs. Real acquisition runs only on Kaggle.

Local contract checks, no media downloads:

```powershell
.venv/Scripts/python.exe -m pytest experiments/image_pool/test_pool.py experiments/scene_array_cache/test_scene_arrays.py -q
.venv/Scripts/python.exe experiments/image_pool/build_notebook.py
.venv/Scripts/python.exe experiments/image_pool/validate_notebook.py
```

The last command executes all cells with twelve softwarefixtures and saves an executed notebook and
artifacts under `runs/fixture_<UTC>/`. Fixture SPI outputs are explicitly marked and are not training data.

Kaggle configuration:

- `IMAGE_POOL_TRAINING_ROOT`: mounted completed4,000-image training run containing
  `selected_manifest.json`, `labels.jsonl`, `progress.json`, `comparison/records.json`, study status,
 48pair selections, heads and exact encoder identities. No silent historical1,000fallback.
- `IMAGE_POOL_MANAGED_MANIFESTS`: optional JSON mapping source names to accessible per-file JSONL
 manifests. See `PLAN.md` for schema, temporal IDs and access fields. Missing sources are explicit.
- `IMAGE_POOL_RESUME_DIR`: matching previous run directory; source/model/input mismatches fail.
- `IMAGE_POOL_MODE`: real on Kaggle, fixture locally. Real local acquisition is rejected.

Output for the teammate: `runs/<id>/handoff/image_parameters.jsonl` plus `pool_manifest.json`, scene
registry, source/model identity and separate reference records. Student SPI predictions are experimental;
mission relevance, novelty and any synthetic time/location are generated by the simulator.
The pool is not fully available until acquisition and producer gates succeed. No cloud run submitted yet.
