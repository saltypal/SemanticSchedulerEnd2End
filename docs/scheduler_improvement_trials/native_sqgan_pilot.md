## Run qualification

The user-supplied ZIP contains run `20261028T130100Z-eea4f3aa`. The extracted files matched the bundle manifest. The actual fine-tuned checkpoint matches the historical scheduler receipt. The earlier runner contained a shortened hash string. The pin was corrected from the archived receipt before running the verified checkpoint.

The native run used the archived scheduler source adapter and pinned upstream SQ-GAN commit `0e5cdd7c0240b89749dad684645c53f783ac24cc`. Weights and upstream sources stayed outside the scheduler checkout. Six LADI validation images were selected from the prior development cohort, with three native visible-road-damage positives and three negatives. Selection used the first three in each class. CPU measurements used two Torch threads and a warm-up image.

All six images produced valid SQ01 payloads and finite reconstructions. Five had a defined road-retention cue. One had no teacher-predicted road in the valid content and used the unavailable representation. The cue is one byte when serialized. Sender prep in the replay includes the separately measured SPI pass. The SPI pass used the archived CLIP weight file and numerical head. The installed processor configuration hash differs from the archived processor hash, so the predictions are a local reproduction of the provisional SPI path. The six predictions were four High and two Low. There were no independent Critical references.

The frozen reader, at its original 0.5 threshold, found 1/3 positives on original images, 1/3 after the resize stage, and 0/3 after SQ-GAN reconstruction. There were no false positives in this small batch. The three positive reconstruction scores were about 0.2004, 0.0043 and 0.0024. This test exposes a reader/codec qualification gap. It does not quantify degradation on an independently held-out population or support lowering the threshold on these same six images.

## Matched development replay

Four fixed workload cycles reuse the same six measurements, with 24 offers per scenario. A seeded permutation changes the order between cycles. These are repetitions of six images rather than 24 independent samples. The policies share captures, complete arrival times, sender costs, payload identities, measured decode and reader durations, and deadlines. There are three nominal loads, each with and without bursts. Delivery is ideal and captures are synthetic.

The cue changed dispatch order relative to SPI-first in four of six scenarios. At bursty overload, SPI-first had 203.45 s p95 observed queue wait and SPI-first plus the cue had 235.58 s. Each had one unfinished decode and one unstarted job. No policy produced a timely correct positive at the frozen threshold. Thus the cue changed ordering but demonstrated no task benefit on this batch. The replay regenerated byte-for-byte, and the augmented receipt's parent hash matches the native measurements.

## Decision

Keep the SQ-GAN simulator and header cue as development tools. Do not promote the cue or refit a scheduler using these six rows. The grouped cue diagnostic refused evaluation because the sample has no independently identified event groups. Critical preservation is also unmeasured. The protected holdout remained closed. The next scientific gate is a development cohort with independently reviewed road outcomes across events and a frozen reader that can identify enough positives after native decoding. Compare cue versus SPI on that cohort before any final evaluation.
