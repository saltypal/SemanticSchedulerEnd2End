# Fix plan after the first learner wave (2026-11-13 night)

Evidence: training curves of the 150-iteration wave; laptop greedy check on 300 val images (c = 2, rho = 1.2, one
realisation, indicative only); literature below. Rule: small fixes and trend checks on the laptop, big training on Kaggle.

## What the check showed
| Finding | Evidence |
|---|---|
| Ranking learners always dispatch B = 8; SV-DPP and BCEdge adapt B | 40 decisions vs 65 (SV-DPP) / 77 (BCEdge) per 300 images; CTR 0.22-0.26 vs 0.56 / 0.50 |
| Ranking quality of SCOPE-DQN / DQN is good | 15.0 / 17.5 inversions per 100 vs SV-DPP 24.6 |
| PPO evaluates worse than random | CTR 0.00, 72.5 inversions per 100 |
| SV-DPP gain may be batching, not semantics | semantic precision 0.54 vs EDF 0.80 |
| SCOPE never leaves the teacher | lambda = 0, tier success ~1.0 from iteration 0 |

## Literature used
| Paper | Lesson for us |
|---|---|
| RLScale-Bench, arXiv:2605.26418 | A calibrated rule-based controller beats six DRL algorithms on steady load; RL helps only on bursty/flash traffic. Calibrate baselines, 5 seeds, several workload patterns, report where RL wins. |
| Adaptive inference batching with PG, arXiv:2607.05272 | On a single GPU with Poisson load RL only matches static batching; RL wins (3.5x) when it jointly chooses routing and batch composition across GPUs. The action must include the batch decision. |
| Differentiable DES for queueing control, arXiv:2409.03740 | Plain PPO fails in queueing; BC init stabilises but does not beat c-mu; a work-conserving policy parametrisation lets PPO beat c-mu. |
| Zeroth-order policy optimisation for queueing, arXiv:2611.01186 | PPO gradients are too noisy in queues; evaluating perturbed policies by average cost (accept only if better), from a BC-pretrained c-mu/MaxWeight start, beats PPO. |
| TGRL, arXiv:2307.03186 | Fixed teacher weights trap the student at the teacher; balance imitation vs reward adaptively by comparing with a reward-only policy; the student then surpasses a sub-optimal teacher. |
| Semantic/importance-aware scheduling (e.g. arXiv:2606.29052) | The gain is shown by running the same scheduler with importance removed, noisy and oracle. |

## Fixes, in order
| # | Fix | Where | Done when |
|---|---|---|---|
| F1 | **Header proofs + batching control.** SV-DPP with full header / SPI only / no header (uniform belief) / genie, plus a new control **EDF + SV-DPP batch rule** (same batching, no semantics). | laptop, ~1-2 h | Semantic claim holds iff full header > no header and SV-DPP > EDF+batch with CIs |
| F2 | **Learners choose order, a shared rule chooses B.** Ranking learners use SV-DPP's renewal-ratio batch-size rule over their own ranking (option: add B as a second discrete head). | laptop code + tests | Learner decisions/300 ~ SV-DPP's |
| F3 | **PPO evaluation bug.** Check greedy decode of the Plackett-Luce output (sign/ordering), work-conserving masking of infeasible jobs, BC warm start from SV-DPP. | laptop | PPO greedy >= BC on the 300-image check |
| F4 | **SCOPE: TGRL-style teacher weight** (compare with reward-only policy, raise/lower imitation weight) instead of the fixed beta decay. | laptop code, Kaggle train | lambda or teacher weight moves; student != teacher |
| F5 | **Harder training regimes** where the teacher is weak: rho 1.5, MMPP bursts, noisy SPI. Train and report per regime (RLScale-Bench protocol). | Kaggle | SCOPE beats SV-DPP in at least one regime with CIs, else reported as negative |
| F6 | **Zeroth-order tuned SV-DPP (optional, cheap)**: search SV-DPP's few parameters (V, beta, tie_tol, purge) by perturb-evaluate-accept on val. Also covers the missing beta / tie grid. | Kaggle CPU | best params frozen before compare sweep |
| F7 | Retrain all learners with fixes (valid independent seeds: 3), then compare sweep | Kaggle | — |
| F8 | AWGN link model before the final sweeps; explainability at the end | laptop | — |

PPO, BCEdge and DQN stay as baselines whatever the result; the paper claims a learner only if it beats SV-DPP with CIs.
