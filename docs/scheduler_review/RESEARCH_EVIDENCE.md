# Bounded evidence review: semantic decoder scheduling

24 October 2026. Read-only research/design assessment of `07_MASTER_EXECUTION_PLAN.md` and `parameter_audit/FINDINGS.md`; this memo is supporting evidence, not a replacement canonical plan. No model training, dataset download, code change, or new scheduler result. The audited source revision is the plan's `2f16785a16dd9c58ce12c98b502087cc212b279b`; plan and findings were read from the current mutable working files.

## Decision consequences

**Retain:** whole received latent, single nonpreemptive decoder, H0 header boundary, causal sender KB/N, completion history, direct-I comparison, supervised contextual marginal-gain hypothesis, separate H1 track, and conditional RL gate.

**Change/strengthen:** formalize three different claims; choose a small dataset portfolio by annotation capability; make feature/hyperparameter selection fully nested and grouped; compare a strong contextual tabular baseline and short planning before PPO. The largest scientific risk is unverified meaning/correspondence in the target, followed by insufficient runtime information. Network depth is currently a secondary uncertainty.

## 1. What can be claimed

1. **Native-label utility:** prioritize images with independently supplied damage/relevance labels. This supports a task-specific utility-ranking result. Severity is not automatically urgency, lives saved, response cost, or general semantic importance.
2. **Controlled duplicate handling:** repeated original-image IDs establish exact-copy suppression under the chosen queue generator. Deterministic headers provide a shortcut. Keep this as a control with its own result, not evidence of different-view fact recognition.
3. **Asset/condition evidence coverage:** requires independently verified correspondence and a fixed fact ontology. This is the main proposed semantic contribution, presently an evidence gap. A new queue seed, similarity cluster, caption, or class label cannot supply missing asset identity.

The current plan already acknowledges most of these boundaries; the execution gates should enforce them. Existing findings are development evidence: C is exposed, F is entirely unavailable, and N's receiver-new AUC near chance is conditional on the controlled-ID protocol. It does not invalidate sender-KB novelty.

The source audit supplied by the lead identifies an even stronger restriction: current `native_utility` follows the same LADI label/importance weighting used by the importance producer, and coverage facts are singleton original-image IDs. This is a valid prediction-versus-native-label check, but only for that explicit severity rubric. With one weighted fact per original image, true distinct-ID greedy is **exactly optimal for A_K**: schedule one occurrence of each available original in descending weight; copies have zero remaining gain. Thus the current synthetic-repeat benchmark has no privileged planning headroom for RL by construction. An RL gain can only reflect utility/duplicate estimation differences or a comparator weakness, not superior planning of that objective.

**Objective limitations (deductions from the proposed definition):** the fact union values a new asserted fact and gives repeated confirmation zero value. That is coherent for evidence coverage but omits corroboration, contradictory evidence, confidence improvement, and downstream action utility. Fact granularity can change rankings: one asset described with ten child facts can outweigh ten assets with one fact each. Freeze an asset-condition decomposition and parent/child credit rule; report a coarse asset-condition sensitivity alongside the chosen fact rule. Do not claim a universal definition of semantics.

Source images support *visible evidence*, not necessarily true hidden structural condition. Native labels and reviewed fact weights are an operational rubric. Explicitly distinguish this from verified physical damage and calibrated emergency decisions.

**Tractable portfolio (recommendation):** LADI + one MEDIC/CrisisMMD source path + one UAV source, with optional small Incidents hard negatives. Add xBD only if satellite transfer or geospatial building evidence is an actual claim. More datasets do not fix missing correspondence. Allocate the plan's 300–500-image development annotation budget across these domains and a *separate verified-correspondence subset*, rather than pretending all examples have the same truth resolution. Choose final sample size after a provenance/annotation yield and group-variance pilot; an image count is not power.

A concrete small work allocation inside that existing budget is **360 development images: 120 LADI + 120 MEDIC + 120 RescueNet**, replacing RescueNet with FloodNet if flooded access is the main question. Sample LADI/MEDIC across documented events, and UAV data across recoverable flight/site groups; actual group availability is unverified. Independently label the same two profiles on every image: (a) visible building-damage evidence and (b) visible road obstruction/flood-access evidence, with absent/irrelevant/uncertain states. Native MEDIC infrastructure labels alone do not establish road obstruction. Aim to identify a 60–100-image correspondence panel *within* this allocation, conditional on provenance; this is an annotation-yield target, not an assertion that those matches exist. Keep new locked final groups outside this development allocation. This is sufficient to test the mechanism's feasibility, not to assert publication power or broad universality.

Check event identity across dataset names. Harvey appears in FloodNet, CrisisMMD and the official xBD examples; Michael appears in RescueNet and xBD. LADI's overlap with these actual events must be audited rather than assumed absent. Dataset-held-out and event-held-out are distinct experiments. Broad event/source mixes can contain the same underlying photograph or site; cross-source near-duplicate review is required.

**Correspondence feasibility:** use geolocation/acquisition plus visual landmarks and independent review to propose matches; admit ambiguous/unavailable status. Similar-looking different buildings and same-building/new-condition pairs are essential negative controls. Crops/augmentations with known parent polygons can form a clearly labeled controlled partial-overlap test, but do not become real different-camera-view evidence. If native provenance cannot support matching, reduce the claim or acquire a suitable cohort; do not manufacture asset IDs.

## 3. Strong policy comparisons and the RL gate

Closest mechanism is relevance-plus-redundancy ranking, not a new communication-layer allocation problem. Original MMR explicitly balances query relevance against maximum similarity to previously selected items; its original evaluations are text reranking/summarization, not disaster-image asset correspondence. Retain a calibrated MMR-style baseline and state that the image/evidence adaptation is being tested. [Inspected formula and evaluations](https://aclanthology.org/X98-1025.pdf).

Minimum serious comparison: direct I; calibrated linear utility and a tuned small gradient-boosted/tree model; the signature control; learned directional overlap + utility; a **contextual tabular model** with candidate fields/masks, completed-history nearest distances/max similarities and count/progress summaries; the proposed DeepSets scorer; then two-step lookahead over the same learned gain model. All tuning uses the same permitted information and a declared comparable budget. Without the contextual tabular model, a DeepSets win over pointwise models confounds contextual information with architecture.

H1 additionally needs pointwise descriptor utility and a transparent descriptor-redundancy/facility-location policy. Descriptor clustering can merge distinct similar buildings or separate useful views of one building. Facility location counts representativeness of the offered population; dense duplicate clusters can dominate. Its surrogate optimum is not an oracle for task facts.

**Useful mathematical structure (deduction):** for fixed nonnegative fact weights, source fact sets and successful ideal decoding, C(S) is normalized monotone submodular. For exact marginal greedy, the classic cardinality result bounds every greedy prefix k by at least (1−1/e) times the best size-k set. [Original theorem source](https://thibaut.horel.org/submodularity/papers/nemhauser1978.pdf). Therefore, for any optimal sequence's prefixes O_k,

`sum_k C(G_k) >= (1−1/e) sum_k max_{|S|<=k} C(S) >= (1−1/e) sum_k C(O_k)`.

This also gives that factor for A_K in this ideal setting. It is a guarantee for exact coverage gains, not for the learned scorer. A fixed conditional expectation of coverage given all initial permitted observations also remains submodular; arbitrary fitted marginal scores need not correspond to any coherent submodular set function. Status-conditioned uncertain failure models require separate assumptions.

A_K is equivalently a truncated weighted first-coverage-time objective: each fact first covered at rank t<=K contributes `w_f*(K−t+1)/(K*W)`. This links the work to coverage ranking/min-sum coverage, whose objectives differ from ordinary relevance nDCG. [Inspected related ranking formulation](https://proceedings.neurips.cc/paper_files/paper/2011/file/8757150decbd89b0f5442ca3db4d0e0e-Paper.pdf). With no overlap, equal successful service, and known standalone utility, descending utility already optimizes every prefix; RL has no sequencing benefit in that regime.

Under static H0/H1, semantic contents are never revealed after dispatch; successful completion marks already visible headers as delivered. RL can learn nonmyopic list construction but is not performing semantic active learning here. Genuine adaptive value needs useful outcome feedback, action-dependent future availability, uncertain failures/costs, or changing arrivals; those do not inherently require RL either. Adaptive greedy guarantees in the literature require explicit adaptive monotonicity/submodularity assumptions, not merely a queue and a reward. [Definitions and assumptions](https://arxiv.org/pdf/1003.3967).

**Gate:** separate estimation, context, information and planning gaps using the plan's tiny fact-aware exact DP, marginal greedy and permitted-input greedy/lookahead. A large fact-oracle gap may be missing information. Test PPO only if a meaningful planning gap remains and same-information short planning fails at acceptable cost. Report equal actor/inputs, comparable tuning, and inference/training cost; do not call generic PPO plus DeepSets a demonstrated new algorithm.

## 4. Empirical feature selection without test reuse

**Evidence:** model selection can overfit finite validation data; selecting once outside evaluation produces optimistic estimates. Cawley/Talbot explicitly require repeating selection inside each evaluation fit and show selection bias comparable to model differences. [Methods and original experiments, especially §5](https://jmlr.org/papers/volume11/cawley10a/cawley10a.pdf).

**Recommended operationalization for this project:**

1. Freeze a new untouched final group manifest. All existing audit/test-exposed images are development-only. Build connected duplicate/correspondence groups before queues. Use global real-event grouping for event-transfer claims; site/flight grouping for within-event claims. If too few independent groups exist, report the limitation rather than using queue count as n.
2. On development data use outer grouped evaluation and inner grouped selection. Inside each inner training fold fit preprocessing, Q calibration, any trainable producer, PCA, overlap estimation, model weights and training histories. Any label-dependent component belongs inside the fold. Frozen pretrained components retain their provenance and cannot be declared event-unseen if trained on the held event.
3. Treat `(feature subset, model family, hyperparameters, loss, overlap strength)` as one selection procedure. Compare folds on paired episode A10, aggregating independent groups with fixed task weighting. Select by the actual scheduling endpoint; predictive error is diagnostic. Freeze search budget and practical tie rule; prefer fewer fields/lower cost when inner differences are smaller than the prespecified tolerance.
4. With eight scalar fields there are 255 nonempty subsets. If N is mandatory in every scorer, there are 128 N-containing subsets. Wire retention/KB preservation and whether a scorer uses a field are separate decisions; do not interpret an ablation as deletion of KB. For a cheap linear/tree search, enumeration *inside* inner folds is feasible; nested evaluation controls optimism, not search cost or variance. For neural policies use a limited prespecified candidate set, chosen on exposed data, rather than 255 times every architecture.
5. Bundle each field with its validity mask when testing inclusion. Separately run masks-only and missingness-matched controls; missingness can identify source/task/calibration support. Permutation importance alone is unreliable for correlated fields and out-of-distribution feature combinations; treat it as a supporting sensitivity check, not a causal field definition.
6. Evaluate the selected procedure once in each untouched outer group. Do not choose a global subset from the outer winners and reuse outer scores as its unbiased performance. Report selection frequency, paired outer effects and variability; with few groups, feature stability remains uncertain. Then refit the frozen selector on all development groups and run the locked final cohort once.
7. Task-specific subset selection supports task-specific claims. For an unseen-task claim, hold out the entire task/profile and repeat selection using other tasks only, with compatible field definitions and an available runtime task representation. Three LADI label profiles plus separately tuned heads do not establish open-ended task generalization. Zero-shot domain transfer and target-domain recalibration/few-shot adaptation need separate results.

For a claim about one reusable policy on known tasks, compare a **pooled task-conditioned model** against a pooled model without task conditioning and validation-selected per-task specialists under the same data/tuning budget. A declared task/profile ID is legitimate available information if adopted in the interface; evaluator labels and per-test-task winner selection are not. Per-task specialists are a useful specialization comparator, not a fact oracle. A pooled model beating them on held-out events supports multi-task reuse across those declared tasks; it does not establish unseen-task transfer. Per-task optimal subsets chosen separately are likewise specialist references, not evidence for one universal subset. Using task-dependent producer scores itself carries task information, so an unconditioned pooled scorer is not necessarily task-agnostic; record that dependency.

Unavailable F or unsupported Q cannot be ranked as intrinsically useless. Feature inclusion value, producer construct validity, and extraction cost are separate measurements. Dropping a scorer field saves extraction only when its upstream operations are actually removable and not shared with N or H1.

## 5. Cheapest discriminating checks
